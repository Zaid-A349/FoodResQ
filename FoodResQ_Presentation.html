Context & Motivation
The Urban Paradox: Food Wastage vs Nutritional Insecurity
02 / 15
The Problem Statistics CRITICAL DATA
  • National Discard: Over 68+ million tonnes of edible food wasted annually in India.
  • Hunger Vulnerability: 200+ million citizens suffer chronic malnutrition daily.
  • Commercial Waste: Weddings, banquet halls, and restaurants discard surplus daily.
  • Time Decay: Cooked meals spoil within 4-6 hours if not rapidly claimed.
  • Methane Footprint: Food in landfills contributes heavily to greenhouse gas emissions.
Failures of Current Systems SYSTEM GAPS
  • High Friction Barriers: Existing apps mandate OTPs, passwords, and app downloads.
  • Exclusion of Needy: Street dwellers and hungry seekers lack email credentials.
  • Delayed Communication: Manual NGO helplines take 12-24 hours to arrange pickup.
  • Raw Coordinates: Cryptic latitude/longitude confuses drivers without street names.
  • Fragmented Donors: Restaurants lack a single unified platform to broadcast urgent surplus.
The FoodResQ Solution OUR APPROACH
  • Zero-Barrier Access: Public browsing allows hungry citizens to locate food with 0 logins.
  • Hyperlocal Matching: Proximity radius sorts food from 1 km to 5 km distance.
  • Symmetrical Security: Role-based access protects NGO audits and donor profiles.
  • Smart Geocoding: Auto-translates device GPS coordinates into local neighborhood names.
  • Dynamic Freshness: Live countdown timers invalidate spoiled food automatically.
FoodResQ transforms an urgent perishable logistics crisis into an automated, transparent hyperlocal coordination network.
System Design
Full-Stack 3-Tier Enterprise Architecture
03 / 15
Tier 1: Client Layer FRONTEND
  • React 18 SPA: Modern functional components with Concurrent Mode rendering.
  • Vite 5: Lightning-fast ES module bundler with instant Hot Module Replacement.
  • Tailwind CSS v4: Semantic utility classes with perfectly symmetrical forms.
  • Leaflet.js: Interactive canvas mapping with customized category pins.
  • FoodContext Store: Central state provider for real-time data & auto-expiry.
Tier 2: Application Layer BACKEND API
  • Node.js v22 LTS: High-throughput asynchronous non-blocking event loop.
  • Express 4.19: Lightweight, modular REST API controller pipeline.
  • CORS Protection: Cross-origin security middleware for client verification.
  • Reverse Geocode Proxy: Connects to OpenStreetMap Nominatim service.
  • Atomic Locking: Prevents race conditions during simultaneous food claims.
Tier 3: Data Layer DATABASE
  • MongoDB Atlas: Cloud-hosted distributed document database cluster.
  • Mongoose 8: Schema enforcement, model relationships, and type casting.
  • Replica Sets: High-availability architecture with automated failover.
  • Geospatial Indexing: Scalable 2dsphere indexing for high-speed location queries.
  • Dual-Mode Fallback: Instant browser localStorage sync during offline periods.
Decoupled 3-tier architecture allows independent frontend scaling and backend microservice migration without service interruption.

Server Architecture RUNTIME
  • Node.js v22 LTS: High-concurrency event-driven V8 JavaScript execution.

Complete API Inventory 13 ENDPOINTS

  • GET /api/food: Retrieve all active listings with distance and category filters.

Reliability & Security STABILITY

  • Standard Status Codes: 200 OK, 201 Created, 400 Bad Request, 409 Conflict.
  • Input Sanitization: Verifies email formatting, numbers, and required fields.
  • Graceful Shutdown: SIGTERM handler cleanly closes active database pools.
  • Structured Errors: Clean JSON responses make debugging and toast alerts trivial.
Stateless RESTful endpoints ensure seamless horizontal scaling across cloud containers without session drift.
Data Architecture
MongoDB Atlas Document Models & Mongoose Schemas
06 / 15
User Model & RBAC USER SCHEMA
  • name: String (Required, donor or organization name).
  • email: String (Unique index, trimmed, lowercase validation).
  • password: String (Secure credential storage).
  • role: Enum ['donor', 'ngo', 'admin'] (Controls dashboard access).
  • darpanId: String (Government NGO Darpan ID validation).
  • phone & address: String (Contact coordinates for dispatch teams).
FoodPost Model CORE SCHEMA
  • title & description: Food overview and special dietary notes.
  • quantity: Number of available portions/meals.
  • foodType: Enum ['Cooked Food', 'Raw Grocery', 'Packaged Food'].
  • dietType: Enum ['Veg', 'Non-Veg', 'Vegan'].
  • location: Object { lat, lng, address } for GIS mapping.
  • expiryHours: Lifespan duration for automatic freshness calculation.
  • status: Enum ['available', 'claimed', 'expired'].
RescueHistory & Reviews AUDIT & TRUST
  • RescueHistory: Records foodPostId, donorId, ngoId, and status.
  • Milestone Stages: Tracks ['claimed', 'picked_up', 'distributed'].
  • Timestamps: Audit log of claim time vs actual completion time.
  • Review Model: 1 to 5 star ratings and feedback comments.
  • Trust Metric: Builds accountability scores for donors and recipient NGOs.
Mongoose schemas strictly enforce business logic while preserving MongoDB's native JSON document retrieval speed.
Geospatial Intelligence
Geolocation, Leaflet Mapping & OpenStreetMap Pipeline
07 / 15
GPS Location Capture CLIENT GPS
  • Browser API: navigator.geolocation.getCurrentPosition() with high accuracy.
  • Permission Handling: Non-blocking prompt with fallback to manual address input.
  • Precision Coordinates: Captures exact latitude and longitude coordinates.
  • Real-Time Pinning: Renders donor position marker instantly on the interactive map.
  • Zero Cost: Uses open web standards without proprietary Google Maps API billing.
Smart Reverse Geocoding NOMINATIM
  • The Problem: Raw coordinates (e.g. 12.9716, 77.5946) confuse users.
  • Nominatim API: Queries OpenStreetMap reverse geocoding REST service.
  • Structured Parsing: Extracts road, suburb, neighbourhood, city, and pincode.
  • Readable Result: Formats clean address string: "Indiranagar, Bengaluru".
  • Resilient Fallback: If network times out, safely formats coordinates as text.
Leaflet & Spatial Proximity MAP ENGINE
  • Canvas Tile Engine: Smooth panning, zooming, and cluster rendering.
  • Categorized Markers: Color-coded pins for Veg (Green), Non-Veg (Red), Urgent (Amber).
  • Interactive Popups: Shows meal title, quantity, distance, and direct claim button.
  • Haversine Formula: Calculates accurate radial distance in kilometers.
  • Proximity Sorting: Seekers sort available surplus from closest to farthest.
Automated reverse geocoding transforms abstract GPS coordinates into actionable street-level pickup instructions.

System Resilience
Dynamic Expiry Engine & Dual-Mode State Synchronization
12 / 15
Dynamic Expiry Engine FOOD SAFETY
  • Perishable Risk: Distributing expired food creates health and safety hazards.
  • Timestamp Calculation: createdAt + (expiryHours * 3,600,000) = deadline.
  • 60-Second Heartbeat: App dynamically recalculates remaining shelf minutes.
  • Auto-Invalidation: Once timer hits 0, post status flips to "Expired" automatically.
  • Color-Coded Urgency: Shifts from green (>3h) to amber (1-3h) to red (<1h).
Dual-Mode State Sync RESILIENCE
  • Primary Tier: Real-time REST sync with live MongoDB Atlas cloud cluster.
  • Offline Fallback: Automatic data caching in browser localStorage.
  • Zero Downtime: If backend goes offline, app continues running without crashing.
  • Data Reconciliation: Re-synchronizes pending records upon cloud reconnection.
  • Optimistic Updates: Claims update UI instantaneously before server response.
Client Performance OPTIMIZATION
  • React useMemo: Prevents redundant recalculation of distance coordinates.
  • Lazy Map Tiles: Leaflet canvas tiles load only within visible viewport.
  • Zero Redux Bloat: Clean React 18 Context API keeps JS bundle size tiny.

Engineering Challenges
Technical Hurdles Overcome & Key Innovations
13 / 15
1. GPS Reverse Geocoding GEO PIPELINE
  • The Problem: Raw coordinates (12.9716, 77.5946) are unintelligible to humans.
  • Our Solution: Integrated OpenStreetMap Nominatim reverse geocoding API.
  • Innovation: Automatically parses road, neighborhood, and city on GPS detect.
  • Fallback: Formatted coordinate fallback prevents form submission failures.
  • Result: 100% clarity for pickup drivers and volunteers.
2. Form Geometry Symmetry UI HARMONY
  • The Problem: Login, Donor, and NGO forms had mismatched sizes and jerky shifts.
  • Our Solution: Re-engineered all 3 auth interfaces into a unified geometric card matrix.
  • Innovation: Standardized modal widths, padding tokens, and field styling.
  • UX Win: Smooth tabs, zero modal jumping, and clean role-switching.
  • Result: Enterprise aesthetic matching top-tier commercial web apps.
3. Cloud Database Migration CLOUD DB
  • The Problem: In-memory storage was lost on every server restart.
  • Our Solution: Migrated to production MongoDB Atlas cloud replica cluster.
  • Innovation: Strongly typed Mongoose schemas with hybrid state synchronization.
  • Data Safety: Pre-seeded demo accounts allow one-click testing without setup.
  • Result: High-availability persistent database accessible anywhere.
Rigorous engineering discipline turned real-world integration hurdles into reliable, user-friendly production features.
